# SDD (Spec-Driven Development)

## O que é?
Metodologia que o contrato (especificação) vem antes de qualquer linha de código. A especificação se torna a **Single Source of Truth (SST)** para todo o ciclo de vida do software.

Essa SST não é imutável, ela é apenas a referência absoluta naquele momento. Quando é necessário fazer uma mudança na SST (seja uma nova feature, alteração nos requisitos, ...), abre uma nova branch, abre PR, como seria normalmente. A diferença é que isso é feito no arquivo JSON/YAML.

## Fluxo padrão
1. **Update no YAML.**
2. **Validação do YAML** com ferramentas como linters.
3. **Prompt:** Você fornece a SST e diz: "Com base nesta especificação, gere/atualize..."
4. **Obs:** Em sistemas gigantescos, onde a spec seria grande demais para o contexto, usa-se RAG para buscar as partes da spec relevantes para a tarefa que o agente está executando.

## Comentários
* Já existia antes do boom das IA's, mas foi adotado por ser excelente para a abordagem *agent-first*.
* Esse estudo foi direcionado para o contexto de *agent-first*.
* É considerado o padrão ouro nesse contexto.
